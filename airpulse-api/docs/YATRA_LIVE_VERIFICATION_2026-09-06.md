## Repairs

- The Yatra verification endpoint now calls the shared engine resolver, with
  the same Yatra adapter as the collector. It cannot enter the older generic
  browser/corridor-model fallback path.
- The isolated Scrapy runner supports the modern async `start()` entry point,
  requests only one results page, disables retries, classifies non-2xx responses,
  uses the Yatra parser, and reports final URL/body size without response cookies.
- Yatra parser preserves unknown flight details and fare components as null;
  multiple unlabeled currency amounts are treated as ambiguous. Collector
  departure timestamps use IST instead of falsely labeling Indian times UTC.
- Playwright resolves its lazy browser before checking availability and checks
  for challenges again after rendering. Empty DOM alone is not no availability.
- The UI defaults to Yatra/T+7/10 fares, uses backend stage results, and no longer
  invents flight identities, departure times, fare totals or tax breakdowns.
- Review configuration is explicit; development mode alone no longer authorizes
  Yatra collection. Imported data support is unchanged.

## Policy and reproduction

Policy remains `MANUAL_REVIEW_REQUIRED`. Reviewed references:
[robots.txt](https://www.yatra.com/robots.txt) and
[master user agreement](https://www.yatra.com/online/yatra-user-agreement.html).
These references are review inputs, not an assertion of blanket permission.

After recording a controlled-test review, configure `YATRA_PROTOTYPE_ENABLED=true`
and nonempty `YATRA_REVIEW_NOTES` in the backend environment and run from
`airpulse-api`: `python -m scripts.probe_yatra`. The default remains disabled.
The probe emits a structured result and performs no canonical database writes.
